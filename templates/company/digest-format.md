# 摘要与消息格式（团队版）

> 规则：一屏读完；**所有待回复的问题合计最多 3 个**（包括「要不要登记」），多出来的写「另有 N 个待回复」；没变化的不写；每个问题都用「D编号 + 选项」回答；每条消息都带事项 ID 或 D 编号，方便以后搜索。
> 下面的人名、频道、项目都是虚构的示例，不要照抄。

## 每日摘要（发在发帖白名单里的约定渠道）

```
📋 <项目/频道名> · 每日摘要 · MM-DD（周X）　　数据：✅ 来源都读到了 ／ ⚠️ 这次没读到 <来源>

🔴 等决定（请审批人私信我回复「D<编号> <选项>」，也可以回「D<编号> 延期 <日期>」「D<编号> 暂停」「D<编号> 取消」）
D<编号> <一句话问题>（已等 X 个工作日｜审批人：<名>｜原帖：<链接>）
    A <选项>（推荐：<一句理由>）  B <选项>  C 先放一放
    不回复：保持现状
（另有 N 个待回复）

🟡 进行中，有风险
- [L-…] <事项>（负责人：<名>）：<风险一句话>

🕸 超过 3 个工作日没有动静
- [L-…] <事项>（负责人：<名>）：上次更新 <日期>

✅ 已关闭（附证据）
- [L-…] <事项>：<证据链接>

❓ 要不要登记成待办？（请 <审批人> 私信回复「D<编号> 登记」或「D<编号> 不用」）
D<编号> <原话摘要>（来源：<链接>）
```

没有任何事时：

```
📋 <项目/频道名> · 每日摘要 · MM-DD　本轮检查完成，无新事项。
```

**不要写**：任何受限来源的内容或存在，包括「私有频道有 1 件事」这种说法。

## 原帖下的提醒（`confirm` 阶段起；`confirm` 阶段要流程负责人先确认）

```
👋 [D<编号>] <审批人>，这个评审已经等了 <N> 个工作日。方便的话请私信我：
「D<编号> A」通过 ｜「D<编号> B」需要修改 ｜「D<编号> 延期 <日期>」
```

## 告诉执行人「决定已记录」

```
📌 [D<编号>] 决定已记录：<审批人> 选了 <选项>（原话：<链接>，<时间>）。
这条通知不构成执行授权。请你核对原话后回复我「已接手 L-<执行事项编号>」。
完成后在原帖贴结果链接，我会按完成标准核对后记录。
```

## 「还要吗」（只问一次，之后不再主动提醒）

```
[D<编号>]「<标题>」已经等了 <N> 个工作日。还要继续吗？
请 <审批人> 私信回复「D<编号> 延期 <日期>」｜「D<编号> 暂停」｜「D<编号> 取消」。
不回复就保持现状，我之后不会再提醒这件事。
```

## 延期确认

```
好的，[D<编号>] 延期到 <YYYY-MM-DD 周X HH:MM>（<时区>）。到时候我会重新放进摘要。
注意：这个决定的有效期仍然是 <有效期>，延期不会延长它。
```

## 不接受的回复

```
谢谢。[D<编号>] 需要 <审批人> 本人确认，所以这条回复我没有记录。
```

```
[D<编号>] 已过期 / 已被 D<新编号> 取代，请看 D<新编号>。
```

## 给流程负责人的私信（卡住、异常或需要升级）

```
⚠️ [L-…/D<编号>] <一句话情况>。我的建议：<建议>。需要你决定：<问题>（请回「D<编号> <选项>」）
```
