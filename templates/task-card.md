# 任务卡：leader 怎么给 AI 派活

> 从 micromanage 变成 leader，最具体的一步是改变派活的方式：**给结果和边界，不给步骤**。
> 依据：Claude Tag good habits（「Give Claude the destination, not the route」「Give every task a definition of done」「Say which decisions come back to you」），以及 Levels of Autonomy 论文。

## 模板（口述也行，语音助手、手机语音都能说）

```
目标：<要什么结果，不是要做什么动作>
完成标准：<看得到的条件>；谁来关：<AI 自己（客观检查）/ 我（批准）>
截止：<时间>
你自己定：<哪些决定不用问我>
必须问我：<哪些决定要回来找我>
汇报：<只在完成或卡住时 / 每天一行>
```

## 例子：同一件事，两种派法

**TL 式（你得一路盯）**

> 帮我看看报名页为什么提交后没跳转。

结果：AI 查完给你一大段分析，你再决定改不改、什么时候上、上完测不测。每一步都要你在场。

**Leader 式（你只出现两次）**

> 目标：报名页提交后自动跳转到确认页。
> 完成标准：在测试环境提交 3 次都跳转成功，并附录屏；谁来关：我，看你给的录屏。
> 截止：周五。
> 你自己定：改哪个文件、怎么修、加什么日志。
> 必须问我：上线时间（活动报名高峰期不上线）、要不要改后端接口。
> 汇报：修好待验收时告诉我，或者卡住超过半天告诉我。

结果：TPM 把它记进账本，worker 去做，你只在「批准上线」和「验收」时出现。

## 三个习惯

1. **说不清完成标准的，先别派任务，改成一个问题**，例如「A 和 B 哪个好，给我推荐」。
2. **同一类事情批准了三次，就考虑写进决策权表**，下次不用再问（要明确写下来，不能默认）。
3. **卡住超过一天的事，先问自己是不是缺了一个决定**。多半是你还没给答案，而不是 AI 不够努力。
