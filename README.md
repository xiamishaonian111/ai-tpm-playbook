# AI TPM Playbook：让 AI 助手像项目经理一样主动跟进

> 调研时间：2026 年 10 月。Claude（Anthropic）和 Codex（OpenAI）一起完成：两条独立调研，三轮挑刺式审查，加上在一个测试环境里的实测。
> 语言：简体中文（产品名和术语保留英文）。

## 这是什么

现在用 AI 的方式，大多是「有需求就开一个对话」。人就得一直盯着：记得哪件事交代过、去催进度、在不同对话之间转述。

这份仓库调研的是另一种用法：AI 像真实员工一样，部署完东西会自己跟踪；有一个像 **TPM（技术项目经理）** 的角色汇报进度、推动进度，甚至反过来提醒人做决定。人从 micromanage 的 TL 变成真正的 leader。

仓库里有三样东西：

1. **调研**：2026 年下半年各家「主动型 AI」产品（Meta Muse、OpenAI dots、xAI Grok Bot、Anthropic Claude Duet 等）怎么做到主动，背后的共同设计模式，工程实现，以及阅读清单。
2. **实施手册**：一份写给「能力一般、会照字面执行的 AI」的手册，教它一步步给自己加上 TPM 能力。附模板和一个账本校验脚本。
3. **验证与复盘**：哪些结论实测过、哪些只是推断，以及审查中发现并修正的问题。

## 一页结论

**1. 2026 年 8 到 10 月，主流厂商都发布了「主动型 agent」。**

| 产品 | 发布 | 一句话 |
|---|---|---|
| Meta **Muse** | 2026-09-08 | 个人 agent，跑在专属云 VM 上；有变化或需要你时回来找你 |
| OpenAI **dots** | 2026-09-29 | ChatGPT 里的 always-on agents；没人用时在后台只读地找能帮忙的事 |
| xAI **Grok Bot** | 2026-08-11 | 「A chief of staff sits on top, with a specialist for each lane」 |
| Anthropic **Claude Duet** | 2026-10-21 | 每天早报，每隔几小时检查，敏感动作先问你 |

它们的共同形态是：自己的云电脑、每天早报、周期检查、敏感动作先问。但都只连得上邮件、日历、Slack 这类 SaaS，**连不到你自己的内部系统**。→ [01 产品全景](01-产品全景.md)

**2. 「主动」靠的不是模型更聪明，而是系统里多了五样东西：** 时钟、账本、清单、规则、渠道。→ [02 设计模式](02-设计模式.md)

**3. 落地方法（[07 手册](07-公司AI实施手册.md)）：**
- 先做**能力自检**（7 项），填完**上线参数表**
- **第一期只跟踪一件事**，例如设计评审跟进
- **三阶段上线**：影子（只读、只出摘要）→ 人工确认后才提醒 → 有限自动。每阶段要 18 项验收全部通过，再加上负责人一条新的批准消息，才能往下走
- **六条红线**：
  - 没有有效的阶段批准就什么都不做
  - 沉默不等于同意
  - AI 发的通知不算执行授权
  - 所有改变状态的回复都按平台账号 ID 核对身份和权限
  - 不越过来源的可见范围
  - 不羞辱、不轰炸
- 按平台给了落地方法：Discord bot 加带权限范围的 API、Slack 加 Claude Tag、Claude Code、自研 agent、Paperclip

**4. 两个最重要的教训：**
- **简报变噪音是这类系统最常见的死法。**（这是推断，依据是各家产品都强调「只在有变化时通知」。）所以第一期只跟踪一件事，每份摘要最多 3 个待回复问题。
- **给 AI 配一个 AI 经理，单靠这一步不管用。** Anthropic 的 Project Vend 实验里，CEO agent 和店长 agent 有同样的盲点；真正起作用的是流程和角色分离。

**5. 审查发现的最危险的坑**（详见 [08](08-复盘.md)）：
- 「72 小时不回复就按推荐的办」等于把沉默当同意
- 「未启用」时到点照样发消息
- 只核验「D7 A」，不核验「D7 取消」
- 采集失败时把旧故障误报成「已恢复」
- 校验器通过，不等于批准有效或事项真的完成
